SFN Logs v2.0.13 — установка (папка moonloader)
================================================

ЧТО ПОЛОЖИТЬ (ровно 2 файла, с заменой):

    GTA San Andreas\moonloader\SFNLogs.lua                 ← заменить старый
    GTA San Andreas\moonloader\lib\fAwesome6_solid.lua     ← положить/заменить (иконки)

Всё. Больше из этого пакета ничего не нужно.

Уже должно быть в moonloader\lib (появилось вместе с Evolve Logs / moonloader):
    lib\mimgui\        — без него окно не отрисуется вовсе;
    SAMPFUNCS (samp.events) — для автоперехвата чата; если его нет, скрипт
    запустится, но лог придётся собирать вручную (/sfnlogcap, /sfnlogadd).

РЕКОМЕНДУЕТСЯ перед запуском:
    Удалить папку  moonloader\SFNLogs\  (старый config.ini и кэш roster.json
    от прошлых версий). Скрипт создаст её заново и сразу подтянет состав
    и журнал из Evolve Logs API (San Fierro News, фракция 9, сервер
    saint-louis — зашито в скрипт, настроить нельзя и не нужно).

ЗАПУСК И ПРОВЕРКА:
    1. Зайти в игру, дождаться загрузки SAMP.
    2. В чате должно появиться:
         [SFN Logs] v2.0.13 загружен. /sfnlog - окно, /sfnlogmembers - состав из игры
         [SFN Logs] источник данных: Evolve Logs API, SF News [9] @ saint-louis
       Если такой строки нет или версия не 2.0.13 — значит заменился не тот файл.
       Сразу после загрузки появится строка «[SFN Logs] запрашивающий: Ваш_Ник
       (ваш ник в игре)» - по ней видно, что ник для API определился верно.
    3. /sfnlog  (или F8) — открыть окно. Дизайн: тёмное окно без заголовка,
       слева малиновое меню «Журнал / Поиск / Настройки / О скрипте».
       В «Журнале» с 2.0.12 нет кнопок «+ Добавить сотрудника», «Уровни из
       игры» и «Экспорт» (решение редакции): добавление - /sfnlogadd и
       «Поиск -> В состав», выгрузка - /sfnlogsave.
    4. /sfnlogapi — статус API (сколько записей pulled, транспорт, ошибки).

КОМАНДЫ:
    /sfnlog        открыть/закрыть окно
    /sfnlogcap     собрать лог из чата вручную
    /sfnlogadd     добавить запись вручную
    /sfnlogsave    экспорт журнала в файл
    /sfnlogmembers отправить /members и перехватить онлайн-состав фракции
    /sfnlogapi     статус Evolve Logs API   (/sfnlogapi all — полный рефреш)
    /sfnlogui      диагностика интерфейса (DPI, ошибки отрисовки)

СОСТАВ ИЗ /members (новое в 2.0.9):
    Серверная команда /members печатает онлайн-состав фракции: ID, последний
    вход, ник с рангом, «На работе/Выходной», AFK. Скрипт перехватывает эти
    строки сам — можно просто ввести /members в чат, а можно нажать
    «Состав из /members» в Журнале (или «ОТПРАВИТЬ /members» в Настройках).
    Новые сотрудники добавляются в журнал, ранги сверяются, каждый ник
    уходит в очередь Evolve Logs API за официальной историей. Ответ API
    проверяется: «записей нет» (404) — это ответ, а сетевой сбой повторяется
    до 3 раз с удваивающейся паузой (config.ini: [api] retries / retryPause /
    giveUp). Отключить перехват: config.ini, [members] enabled = 0.

    ЕСЛИ В НАСТРОЙКАХ «последний разбор: 0 строк из N»: включите /sfnlogcap,
    повторите /members и пришлите файл moonloader\SFNLogs\chat_dump.txt —
    в нём видно, в каком виде сервер печатает строки. Именно так в 2.0.11
    нашли живой формат Evolve RP «Jonny_Wilde (Voice):» без [ID] после ника.

ТРАНСПОРТ ЗАПРОСОВ (если в чате мелькала строка «переключился на requests»):
    Основной транспорт - downloadUrlToFile: качает ответ в фоновом потоке,
    игра не блокируется. requests - запасной, он подмораживает кадр на время
    запроса, поэтому скрипт сам возвращается на фоновый транспорт, как только
    тот оживёт (тихая проба в простое раз в 5 минут). Закрепить выбор вручную:
    в config.ini, секция [api]:  transport = auto | download | requests
    (auto по умолчанию; download = только фоновый, requests = только блокирующий).

ЕСЛИ ОКНО ВСЁ ЕЩЁ «ГОЛОЕ» (простой текст без дизайна):
    Это аварийный текстовый режим — значит, какой-то вызов ImGui не
    поддерживается вашим mimgui. Сделайте:
        1. /sfnlogui — и пришлите скриншот/текст из чата;
        2. скриншот самого окна;
        3. напишите, какая у вас версия mimgui (обычно видна в
           moonloader\lib\mimgui\ или в логе MoonLoader.log).
    В v2.0.1 уже исправлена главная причина голого окна: вызов
    imgui.GetColorU32(ImVec4), которого в mimgui не существует
    (там это ColorConvertFloat4ToU32). Теперь скрипт сам находит
    рабочую функцию конвертации цвета.

КЛАВИША ОКНА (новое в 2.0.12):
    По умолчанию F8 - открывает И закрывает окно. В «Настройках» строка
    «Горячая клавиша:» показывает текущую клавишу и выпадающий список из 17
    (F1-F12, Insert, Delete, Home, End, PageUp, PageDown). Выбор сохраняется
    СРАЗУ в moonloader\SFNLogs\hotkey.json и работает без /reload; этот файл
    важнее config.ini. Старые конфиги с перепутанными кодами (0x75/0x77/0x70)
    скрипт сам переводит на задуманную клавишу (F8/F10/F1).
    ЕСЛИ ОКНО НЕ ОТКРЫВАЕТСЯ КЛАВИШЕЙ: убедитесь, что не печатаете в чат и не
    открыт диалог SAMP (клавиша намеренно игнорирует чужой курсор и ввод чата);
    смените клавишу в настройках - например, на F10.

ФРИЗЫ ИГРЫ ПРИ ОБНОВЛЕНИИ API (устранено в 2.0.13):
    Симптом из репорта: игра периодически подвисала на 1-6 с при обновлении
    состава, а /sfnlogapi показывал «транспорт: requests (авто)»,
    «переключений: 1», «последний статус: 58». Причина: 58 - это нормальный
    финальный код downloadUrlToFile (STATUSEX_ENDDOWNLOAD), но скрипт знал его
    только из require('moonloader').download_status; где библиотека не
    отдавала таблицу, запрос висел до таймаута, гонка «статус раньше файла»
    давала «пустой ответ», а двух таких сбоев хватало, чтобы уйти на
    блокирующий requests - он и морозил кадр на каждом запросе.
    Теперь: коды 6/58 зашиты явно; конец запроса определяется и по телу
    ответа на диске; после финального статуса файл дожидается до 2,5 с;
    на requests скрипт уходит лишь как на крайнюю меру (8 неудач фона подряд,
    с предупреждением в чат) и раз в 5 минут пробует вернуться; roster.json
    пишется батчами (не чаще раза в 5 с). Проверка: после «Обновить всех
    сейчас» /sfnlogapi должен показывать «транспорт: downloadUrlToFile»,
    «переключений: 0», а игра - не подвисать.

ИСТОРИЯ ВЕРСИЙ:
    2.0.13 — устранены фризы игры при запросах к API (баг-репорт «подвисает
            на 1-6 с, транспорт requests (авто), последний статус 58»):
            финальные коды downloadUrlToFile 6/58 зашиты явно, готовность
            ответа проверяется по телу файла, добавлена дожидалка тела после
            финального статуса (гонка «пустой ответ»), авто-переключение на
            блокирующий requests стало крайней мерой (8 неудач вместо 2),
            проба возврата больше не ждёт пустых очередей, roster.json пишется
            батчами, /sfnlogapi показывает историю статусов загрузки.
            Проверок 426 + 178 + 99; на 2.0.12 новые тесты красные
            (11 FAIL в API).
    2.0.12 — из «Журнала» убраны кнопки «+ Добавить сотрудника», «Уровни из
            игры», «Экспорт» (таблица заняла их место); исправлен
            «запрашивающий» (ник игрока определялся неверно: пара
            (успех, ид) из sampGetPlayerIdByCharHandle читалась как один
            ид); починена клавиша окна и её настройка: цикл звал отсутствующие
            wasKeyPressed/isChatInputActive и умирал на первом кадре, а кнопки
            настройки ставили перепутанные VK-коды («F8» = 0x75 = F6).
            Теперь: фронт isKeyDown, список из 17 клавиш, hotkey.json,
            миграция старых кодов. Проверок 413 + 178 + 81, на 2.0.11 новые
            тесты красные (14 FAIL и 11 FAIL).
    2.0.11 — исправлен разбор строк /members («последний разбор: 0 строк из 11»):
            Evolve RP печатает «Jonny_Wilde (Voice): Программный директор[9]»,
            БЕЗ [ID] после ника, а шаблон требовал обязательный Nick[248] —
            не разбиралась ни одна строка. Хвост между ником и двоеточием
            теперь ловится свободно ([248] (Voice) / (Voice) / [248] / пусто),
            его состав проверяется отдельно (ник не режется по точке), дефис
            перед статусом необязателен. Причина найдена по дампу чата
            (/sfnlogcap -> moonloader\SFNLogs\chat_dump.txt); тесты
            проигрывают живой дамп целиком (сам файл лежит в
            tests\fixtures\chat_dump_2026-09-28.txt): 344 проверки,
            на 2.0.10 — 58 FAIL.
    2.0.10 — исправлен перехват /members («последний разбор: 0 строк из 10»):
            сервер печатает блок не построчно, а несколькими сообщениями со
            строками через перевод строки; скрипт видел из такого сообщения
            только заголовок. Теперь сообщение режется на строки и каждая
            разбирается как раньше. Цвета {RRGGBB} и префикс [ЧЧ:ММ:СС] не
            мешали и не мешают; однострочные сообщения обрабатываются как
            прежде.
    2.0.9 — состав из серверной команды /members: перехват онлайн-списка
            фракции (ник, ранг, последний вход, «На работе/Выходной», AFK),
            автодобавление сотрудников и очередь каждого ника в Evolve Logs
            API; кнопка «Состав из /members» в Журнале и «ОТПРАВИТЬ
            /members» в Настройках, команда /sfnlogmembers. Ответ API теперь
            проверяется «получили или нет»: тело 404 NOT_FOUND распознаётся
            даже в downloadUrlToFile (раньше оно считалось сетевой ошибкой и
            рвало транспорт — «ошибок: 141»), сетевой сбой повторяется до
            3 раз с удваивающейся паузой, затем откат 10 минут; дата принятия
            из /members считается приблизительной, пока API не даст точную.
    2.0.8 — меню сотрудника (ЛКМ по нику в журнале) снова нормальная панель:
            ширина попапа задавалась SetNextWindowSize ВНУТРИ открытого
            BeginPopup — ImGui отдавал этот размер следующему окну, а меню
            автосайзилось по содержимому, которое само себя не расширяет,
            и в точке клика оставалась тонкая вертикальная полоска во всё
            меню высотой (виден был только цветной штрих ранга); теперь
            размер выставляется ДО BeginPopup.
    2.0.7 — наведение мыши на строку журнала больше не ломает раскладку:
            подсказка строки открывалась через BeginTooltip, который в mimgui
            возвращает nil (void), а проверка «if not BeginTooltip()» считала
            nil отказом и оставляла тултип открытым — следующая строка таблицы
            исчезала, кнопки «+ Добавить сотрудника» и «Уровни из игры»
            прыгали внутрь таблицы, у мыши висела пустая рамка; убрана также
            постоянная чёрная полоса под таблицей — это граббер горизонтальной
            прокрутки, включавшийся из-за лишних ~7 px ширины таблицы
            относительно внутреннего региона (теперь колонки подгоняются
            по ширине, прокрутка только при настоящем оверфлоу).
    2.0.6 — транспорт больше не ложно переключается на блокирующий requests
            на старте игры: порог тишины ступенчатый (10 с без единого статуса
            колбэка — холодный старт WinINET/DNS/TLS, 6 с со статусами без
            данных, 4 с после первых данных), первые 5 с после загрузки сеть
            не трогается, в простое на requests раз в 5 минут тихая проба
            возвращает фоновый транспорт; в config.ini ключ [api] transport =
            auto|download|requests закрепляет транспорт вручную; таймаут
            requests 6 с (короче подморозка кадра); диагностика тишины
            в /sfnlogapi.
    2.0.5 — статусы downloadUrlToFile 1..5 больше не считаются ошибкой
            (раньше запрос «умирал» на статусе 2 = соединение: fail:2 и сотни
            ошибок в чате, окно мигало «запрос.../ошибка»); обрыв соединения
            виден за ~4 с; после двух неудач транспорт сам переключается
            downloadUrlToFile <-> requests и обратно; при сериях неудач воркер
            делает паузу 1..30 с; у каждого запроса свой временный файл.
    2.0.4 — длинные тексты в колонках укорачиваются многоточием, а не
            обрезаются по живому: название ранга («Главный редактор»)

    2.0.3 — рангов 9 (потолок «Программный директор», ген.директора в SFN нет);

    2.0.1 — фикс «голового окна»: совместимость конвертации цветов с mimgui
