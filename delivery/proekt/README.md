# SFN Logs — журнал состава San Fierro News

![SFN Logs](assets/logo_source.jpg)

MoonLoader-скрипт для SA-MP (Evolve Role Play, Saint-Louis): ведёт журнал
состава редакции, считает сроки повышений по правилам фракции, следит за
лимитами должностей и уровнями, а официальные данные о рангах берёт из
**Evolve Logs API** (`api.evolvelogs.ru`), фракция 9 (SF News), сервер
`saint-louis`.

Текущая версия — **2.2.4**. История изменений вынесена в
[`CHANGELOG.md`](../../CHANGELOG.md) в корне репозитория: там же версии
SFN_Helper и теги релизов.

Если нужен не только журнал, а журнал вместе со скриптами редакции (фото,
эфир, соцопрос) в одном окне — ставьте [`SFN_Helper.lua`](../../SFN_Helper.lua)
из корня репозитория: он собран на этом же ядре.

## Установка

```
moonloader\SFNLogs.lua              <- скрипт
moonloader\lib\fAwesome6_solid.lua  <- иконки FontAwesome 6 (344 КБ)
moonloader\lib\mimgui\              <- нужен (стандартная библиотека MoonLoader)
moonloader\lib\samp\events.lua      <- для автоперехвата чата (SAMPFUNCS)
```

`encoding.lua` не нужна: конвертацию CP1251 ↔ UTF-8 скрипт делает сам.
Папка `moonloader\SFNLogs\` создаётся при первом запуске:

| файл | назначение |
|---|---|
| `config.ini` | хоткей, секции `[api]`, `[members]` и `[update]` |
| `roster.json` | состав редакции + кеш ответов API |
| `hotkey.json` | выбранная клавиша окна (важнее `config.ini`) |
| `update.json` | состояние автообновления: последняя проверка, доступная версия, ошибка |
| `update.lua.new` | скачанная новая версия (живёт до установки) |
| `export.txt` | результат выгрузки (`/sfnlogexport`) |
| `api_N.json` | временные файлы ответов (транспорт `downloadUrlToFile`) |
| `log.txt` | однократный лог незнакомых кодов загрузки |

## Команды

| команда | действие |
|---|---|
| `/sfnlog` | открыть/закрыть окно (или F8) |
| `/sfnlogmembers` | отправить `/members` и перехватить онлайн-состав фракции |
| `/sfnlogadd Ник [КтоПринял]` | добавить стажёра с текущей датой |
| `/sfnlogsave` | принудительно сохранить журнал |
| `/sfnlogexport` | выгрузить журнал в `export.txt` |
| `/sfnlogupdate [check\|install\|url]` | автообновление: статус / проверить / поставить / показать источник |
| `/sfnlogapi [all]` | диагностика API (транспорт, очередь, повторы) / поставить весь состав в очередь обновления |
| `/sfnlogui` | диагностика интерфейса (DPI, метрики, ошибки отрисовки) |

Две последние команды — технические, обычному пользователю они не нужны.

## Данные и API

- Состав (кто принят, заметки, уровни, онлайн) хранится локально: API не умеет
  отдавать список фракции, только записи по нику. Онлайн-состав пополняется
  перехватом серверной команды `/members` (см. выше), офлайн-сотрудники —
  ручным добавлением (`/sfnlogadd`) или «Поиск → + В состав».
- По каждому сотруднику фоновый поток тянет `GET /v1/journal` (последнее
  событие) и один раз `GET /v1/journal/history` (полная история): официальный
  ранг, дата и инициатор события, увольнение (`Uninvite`), дата принятия
  (`Invite`). Ответ кешируется на `ttl` секунд (секция `[api]` в config.ini).
- Ограничения сервера учтены: не более 4 запросов в секунду, один одновременный
  запрос, таймаут ~15 с у `downloadUrlToFile` и 6 с у `requests`, `requester`
  обязателен.
- Каждый исход запроса проверяется: данные получены — применяются; 404
  `NOT_FOUND` — ник помечается `apiMissing` (повторять бессмысленно); сетевой
  сбой — повтор с удваивающейся паузой (`[api] retries`, по умолчанию 3),
  затем откат на `[api] giveUp` секунд.
- Локальные ручные правки ранга возможны, но перетираются официальными данными
  при следующем обновлении кеша — источник истины один.
- Правила редакции (минимальные уровни и потолок должностей 7–9 рангов) API не
  знает, они считаются локально: `PROMOTE_REQ`.
- Рангов 9: потолок редакции — «Программный директор». Генерального директора
  в SFN нет; если API пришлёт ранг выше потолка, при применении он упирается в 9.
- Транспорт запросов: основной — `downloadUrlToFile` (качает ответ в фоновом
  потоке MoonLoader, кадр игры не блокируется); конец запроса определяется по
  статусам 6/58 (зашиты явно) и по телу ответа на диске. `requests` —
  блокирующий транспорт последней меры: в режиме `auto` скрипт уходит на него
  только после 8 неудач фона подряд (с предупреждением в чат) и раз в 5 минут
  пробует вернуться. Выбранный транспорт виден в `/sfnlogapi` (в «Настройках»
  с 2.1.0 этой строки нет — она техническая).
- Окно рисуется без титульной панели (NoTitleBar), поэтому кнопка закрытия
  своя: крестик в правом верхнем углу, клик по нему закрывает окно
  (открыть снова — `/sfnlog` или F8).

## Окно

Дизайн — визуальный язык Evolve Logs (совместный старый проект): тёмный
сайдбар 160 px с логотипом и градиентными кнопками меню, малиновый акцент
`0.725/0.180/0.263`, полоса раздела с градиентом (значок «‹» убран в 2.1.0:
он читался как несуществующая кнопка «назад»), таблица с центрированными
серыми заголовками и тонкими вертикальными разделителями,
шрифты `arial 13` (ячейки), `arial 15.5` (меню), `trebucbd 20` (заголовок),
иконки FontAwesome 6, серый кружок «?» с подсказкой-причиной (их CustomHint).

Разделы: **Журнал** (состав), **Поиск** (события API по нику, таблица как в
Evolve Logs), **Настройки**, **О скрипте**.

Раскладка при этом остаётся надёжнее оригинала:

- ширины колонок измеряются по тексту (`CalcTextSize`), длинное сокращается
  с «…» или уходит в тултип — наложений нет ни на каких данных;
- все размеры умножаются на `GetDpiScale()` (в их mimgui 1.7.0 DPI не
  поддерживался вовсе, у нас 1.7.1 — поддерживается);
- размер окна пересчитывается под содержимое, минимум — их 1030×520;
- `SetCursorScreenPos` не используется: в ImGui он меняет X всей следующей
  строки, это источник «уехавших» таблиц.

Если в сборке mimgui не хватит примитивов или шрифтов, окно деградирует до
текстового вида и сообщит об этом в чат (`/sfnlogui` покажет причину).

### Настройки (с 2.1.0)

Разделов четыре, в них нет ни одного технического параметра:

| раздел | что внутри |
|---|---|
| **Окно** | горячая клавиша (список из 17), «показывать уволенных» |
| **Состав из игры** | забирать ли ответ `/members`, состояние последнего разбора, кнопка «Обновить состав из игры» |
| **Данные из Evolve Logs** | от чьего имени идут запросы, есть ли соединение, кнопки «Обновить данные всех», «Сохранить журнал», «Выгрузить в файл» |
| **Обновления** | проверять ли автоматически, ставить ли сразу, доступная версия, время последней проверки, кнопки «Проверить обновления» и «Поставить обновление» |
| **Служебное** | путь к `config.ini`, кнопка «Перечитать config.ini» |

Транспорт запросов, счётчики повторов/откатов и время жизни кеша из окна
убраны и доступны только через `/sfnlogapi`; параметры остались в `config.ini`
(секция `[api]`) и по-прежнему работают.

Галочки окна сохраняются сразу (`saveConfig()`, с 2.2.0) — перезапуск игры их
больше не сбрасывает.

### Автообновление (с 2.2.0)

```
[update]
enabled = 1        ; проверять обновления (0 — только вручную, /sfnlogupdate check)
auto    = 1        ; ставить новую версию сразу (0 — предложить и ждать кнопку)
url     = https://raw.githubusercontent.com/Wereskkk/SFN_Logs/main/SFNLogs.lua
every   = 21600    ; как часто спрашивать, секунд (минимум 600)
```

Что происходит при обновлении: скачанный файл проверяется (компиляция, маркеры,
версия строго новее, размер), текущий скрипт сохраняется как `SFNLogs.lua.bak`,
новый записывается на его место и сверяется по длине; при любой неудаче старый
файл остаётся нетронутым. После успешной установки в чат пишется «введите
`/reload` или перезапустите игру».

Откат: удалить новый `SFNLogs.lua` и переименовать `SFNLogs.lua.bak`.

Проверка состояния: `/sfnlogupdate` (версия, когда проверяли, ошибка, счётчики),
`/sfnlogupdate url` (источник и какой файл будет заменён).

## Проверка

Все наборы идут на headless-моке mimgui через lupa (Lua 5.4 внутри Python):
`pip install lupa`, затем из `delivery/proekt`:

```bash
python tests/run_logic.py                # 554 passed — правила, JSON,
                                         # кодировки, /members, saveConfig
python tests/run_ui.py                   # 272 passed — вёрстка окна
python tests/run_ui_strict_colors.py     # DrawList жив, окно не «голое»
python tests/run_api.py                  # 149 passed — сетевой слой,
                                         # автообновление, откат установки
python tests/run_helper_logic.py         # 843 passed — ядро SFN_Helper
                                         # и модули Фото/Эфир/Соцопрос
python tests/run_helper_ui.py            # 192 passed — вёрстка вкладок
python tests/render_svg.py               # preview/*.svg (10 сцен)
python tests/render_helper_svg.py        # preview/helper-*.svg (9 сцен)
```

Тот же набор выполняет GitHub Actions (`.github/workflows/tests.yml`) на каждый
push и pull request: автообновление подменяет файл скрипта у всех игроков
сами, поэтому красная ветка `main` — это поломка у всей редакции сразу.

Тест вёрстки проверяет геометрию: пересечения прямоугольников текста, выход
содержимого за границы окна, баланс `Begin/End` и `Push/Pop` стилей, рост окна
вместе с содержимым, DPI 1.5, аварийный режим без DrawList, а также разбор
реальных форматов API (`Репортер [4]`, `Гл.Редактор`, `Uninvite`,
`10.06.26 14:32`, `29.11.2025 23:22`).

## SFN_Helper

**SFN_Helper** — SFN Logs и три скрипта редакции в одном файле с общим окном
и вкладками в этом же дизайне: `SFN_Helper.lua` в корне репозитория.

| вкладка | модуль | перенос | данные |
|---|---|---|---|
| Журнал, Поиск, Настройки, О скрипте | ядро | SFN Logs 2.2.4 | `moonloader\SFNHelper\` |
| Фото | `photo` | `sfn_photo_helper.lua` v13.4.1 | `sfn_photo_data\photos.json` |
| Эфир | `efir` | `sfn_efir_helper.lua` v7.0.1 | `sfn_data\*.json` |
| Соцопрос | `social` | `sfn_social.lua` v4.0 | `sfn_photo_data\social.json` |

Базы читаются из прежних папок, поэтому переход с отдельных скриптов ничего не
теряет; пол игрока теперь один на все модули (`SFNHelper\genders.json`, старые
файлы сливаются в него при первом запуске). Хоткеи: F9 — окно, F11 — вкладка
«Эфир», F10 — вкладка «Соцопрос»; команды: `/sfnhelper …`, `/efir*`, `/social*`.

Как скрипт редакции становится вкладкой — в `SFN_Helper/CONTRACT.md`; куда
класть новые входящие скрипты — в `SFN_Helper/README.md`. SFN Logs продолжает
жить и обновляться самостоятельно, пока редакция не переедет полностью.

## Известные ограничения

> Важно: Evolve Logs API отвечает только по конкретному нику (`player=...`):
> эндпоинтов «весь состав фракции» у него нет (проверено по документации
> `GET /v1` и ответом 422 без `player`). Поэтому состав собирается самим
> скриптом (вывод `/members`, ручное добавление, «Поиск → + В состав»), а API
> добирает по известным никам ранги, события и историю.

- API не отдаёт список состава и уровни игроков: онлайн-состав берётся из
  `/members`, остальное ведётся локально (`/sfnlogadd`, «Поиск → + В состав»),
  уровни читаются из игры. `/members` показывает только тех, кто в игре —
  уволившиеся и offline-сотрудники попадают в журнал вручную или через поиск.
- Приёма/повышения/увольнения из чата скрипт больше не ловит (2.1.0): события
  приходят из журнала Evolve Logs по нику, а новый сотрудник — из `/members`
  или из поиска. Если игрок не в игре и его ник не искали — в журнале его нет.
- Ранг, проставленный вручную, живёт до следующего обновления кеша API.
- Автообновление заменяет файл скрипта, поэтому не работает, если
  `moonloader\SFNLogs.lua` доступен только на чтение или лежит не там, где
  ожидает MoonLoader (путь берётся из `thisScript().filename`). В этом случае
  скрипт сообщает причину в чат и продолжает работать старой версией.
- Обновление берётся из ветки `main`: коммит в `main` = публикация релиза для
  всех пользователей. Ветку и форк можно указать в `[update] url`.
