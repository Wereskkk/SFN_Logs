# Контракт модуля SFN_Helper

Техническое соглашение о том, как входящий скрипт становится вкладкой общего
окна. Пишу для себя и для ревью: любой модуль, удовлетворяющий контракту,
получает дизайн, DPI, тесты и превью бесплатно; всё, что контракту не
удовлетворяет, refactored до соответствия перед вливанием.

## 1. Структура модуля

Файл модуля после интеграции: `SFN_Helper/src/modules/<id>.lua`. Возвращает
таблицу:

```lua
return {
    id       = 'weather',            -- латиница, уникальный, из имени файла
    title    = 'Погода',              -- подпись вкладки в сайдбаре
    hint     = 'прогноз по Сен-Луи',  -- строка-пояснение в «О скрипте» (опц.)
    order    = 10,                    -- место в сайдбаре (системные: 1..4, 90..99)

    -- ЧИСТАЯ ЛОГИКА: без ImGui, без SAMP API. Попадает в PURE-тесты.
    pure = function(env)              -- env: json, readFile/writeFile, os.time…
        local state = { ... }
        function state.parse(text) ... end
        function state.tick(now) ... end
        return state
    end,

    -- ВКЛАДКА: рисуется только примитивами дизайн-ядра.
    draw = function(ctx)              -- ctx: w, h, now, state, ui-хелперы ядра
        ctx.section('заголовок')      -- полоса раздела (без «‹»)
        ctx.kv('ключ', 'значение')    -- строка ключ/значение
        ctx.table(rows, cols)         -- таблица с замером колонок по тексту
        ctx.button('label', fn)       -- кнопка в стиле flowButton
        ...
    end,

    -- НАСТРОЙКИ: секция модуля в общем разделе «Настройки».
    settings = function(add, cfg)     -- add(t, a, b, c) как в settingsRows()
        add('checkbox', 'Показывать прогноз', ref, function() ... end)
    end,

    -- КОМАНДЫ: регистрируются с префиксом /sfnhelper <id> … и, опционально,
    -- свои короткие алиасы, если они не заняты (проверяется тестом).
    commands = {
        ['']     = function(arg) ... end,   -- /sfnhelper weather
        ['send'] = function(arg) ... end,   -- /sfnhelper weather send
    },

    onLoad    = function() end,       -- один раз при старте скрипта (опц.)
    onTerminate = function() end,     -- перед выгрузкой (опц.)
}
```

Правила:

* модуль НЕ вызывает `imgui.*` напрямую — только через `ctx`-хелперы ядра;
  иначе вкладка не получит DPI-масштаб, замер окна и аварийный режим;
* модуль НЕ пишет в чат напрямую — `ctx.say(text)` (конвертация CP1251/UTF-8
  централизована);
* состояние модуля живёт в его `state` и, если нужно пережить перезапуск,
  сериализуется ядром в `SFNHelper\<id>.json` (модуль объявляет
  `persist = { 'ключи' }`);
* любая сетевая работа — через фоновый воркер ядра (`ctx.fetch(url, cb)`),
  который переиспользует транспорт и бэкофф SFN Logs (downloadUrlToFile /
  requests, статусы 6/58, дожидалка тела); блокирующие вызовы в `draw`
  запрещены.

## 2. Дизайн-ядро

Из SFNLogs.lua 2.2.x выносится в `SFN_Helper/src/core.lua` без изменения
поведения (регресс SFN Logs продолжается до полного переезда):

* палитра `C` + `RGBf/CU/withA`, ранговые цвета;
* масштаб: `refreshScale()`, `S(v)`, `PADX`;
* примитивы DrawList: `fillRect/strokeRect/hline/vline/dot/gradH`,
  `drawText*`, `fitText`, `textW` (кеш измерений);
* потоковые хелперы: `anchoredRow/sameRow/advance/tip`;
* компоненты: `sectionStrip` (без «‹»), `flowButton`, `gradientMenuButton`,
  `menuItem`, таблицы `measureCols/rowsWidth/fitTableWidths`, модалки
  `modalSize/modalHeader/fieldRow`;
* каркас: `pushTheme/popTheme`, `computeLayout/bodyDesired`, сайдбар с
  логотипом, крестик закрытия, `drawFallback`;
* сервис: `say/logEvent`, JSON-кодек, CP1251↔UTF-8, `saveConfig`-механика,
  автообновление (валидация файла, бэкап, update.json).

Ядро меняется только добавочно: новые ctx-хелперы не должны ломать SFN Logs,
пока тот не переехал.

## 3. Окно и вкладки

* сайдбар: системные вкладки `Журнал`(1) `Поиск`(2) `Настройки`(3)
  `О скрипте`(4), затем модули по `order`;
* полоса раздела тела = title вкладки (как сейчас «Журнал состава»);
* окно меряется под самую «толстую» открытую вкладку (уже так в SFN Logs);
* скролл: у вкладок со списками — свой скролл-регион строк с клипом и
  закреплённой шапкой (механика v2.2.2), тело вкладки закреплено;
* попапы/модалки модулей изолированы id-ами (`<id>_##…`), чтобы две вкладки
  не открыли чужой попап.

## 4. Тесты и превью (обязательная часть приёмки)

* `tests/logic_<id>.lua` — PURE-логика модуля (парсинг, правила, персист);
* `tests/run_ui.py` расширяется сценой вкладки: пустая, с данными, DPI 1.5,
  hover, скролл (закреплённые элементы стоят, строки в клипе);
* `tests/render_svg.py` получает сцену `<id>` в `preview/`;
* страховки исходника: модуль не зовёт `imgui.` напрямую, не использует
  `wasKeyPressed`, не пишет в чат мимо `ctx.say`.

CI (.github/workflows/tests.yml) прогоняет всё на каждый push: красный main
= поломка автообновления у всех пользователей.

## 5. Именование и доставка

* итоговый скрипт: `SFN_Helper.lua` в корне репозитория, `script_name('SFN Helper')`;
* автообновление: raw-адрес `main/SFN_Helper.lua`; состояние в том же
  `update.json` (общий механизм), бэкап `SFN_Helper.lua.bak`;
* SFN Logs (`SFNLogs.lua`) продолжает жить и обновляться, пока редакция не
  перейдёт на SFN_Helper полностью; обе версии могут стоять рядом: разные
  имена файлов, разные папки данных (`SFNLogs\` и `SFNHelper\`), разные
  хоткеи по умолчанию (F8 у Logs, F9 у Helper, настраивается);
* версия SFN_Helper стартует с 1.0.0 и включает версию ядра в «О скрипте».

## 6. Что спрашиваю перед сборкой, если неясно из кода

* какие данные пользователь должен видеть в первую очередь (порядок строк/
  колонок вкладки);
* что редактируется прямо в окне, а что только командами;
* что переживает перезапуск игры (персист);
* нужны ли уведомления в чат и в каких случаях.
