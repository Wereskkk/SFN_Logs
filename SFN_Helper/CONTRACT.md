# Контракт модуля SFN_Helper

Как входящий скрипт редакции становится вкладкой общего окна. Документ описывает
**фактически реализованный** механизм (на нём уже работают модули «Фото»,
«Эфир» и «Соцопрос»): всё, что ему не удовлетворяет, приводится к контракту
перед вливанием.

## 0. Где живёт код

Отдельных файлов модулей в репозитории нет: `SFN_Helper.lua` — **собираемый**
файл. Канон ядра — `delivery/proekt/SFNLogs.lua` (он же SFN Logs), слои модулей
добавляются сборочными скриптами в порядке:

```
build_helper_1.py        ядро: имена, папка SFNHelper\, реестр модулей,
                         диспетчеры событий и команд, /sfnhelper
build_helper_2.py        модуль «Фото» + сборка меню (MENU_ITEMS/IDS/STRIP_LABELS)
build_helper_3_efir.py   модуль «Эфир»
build_helper_3b_genders.py  общая база полов + правки «Эфира» под неё
build_helper_4_social.py    модуль «Соцопрос»
```

Правки вносятся в сборочные скрипты, не в `SFN_Helper.lua`: файл
пересобирается целиком, поэтому любое изменение ядра автоматически попадает в
помощник. Каждый шаг asserts'ами проверяет, что якорь найден ровно один раз, —
молча «не вставилось» не бывает.

## 1. Два слоя модуля

Модуль вставляется в два места файла:

| слой | куда | что можно | что нельзя |
|---|---|---|---|
| **PURE** | внутрь `-- >>> PURE LOGIC BEGIN … <<< PURE LOGIC END` | json-кодек ядра, `readFile`/`writeFile`, кодировки, `os.*` | `imgui.*`, SAMP API, `wait`, `lua_thread`, глобалы игры |
| **GAME** | перед `-- == МОДАЛКИ ==` | всё: imgui-примитивы ядра, `say`, `sampSendChat`, `lua_thread`, `isKeyDown` | блокирующие вызовы в `draw` |

Оба слоя оборачиваются в `(function() … end)()` (не в `do … end`): в Lua 5.4
локальные вложенного блока **всё равно** считаются в лимит «200 локалей на
функцию» владельца, поэтому главный чанк файла с тремя модулями через `do…end`
уже не собирался. У функции-обёртки свой лимит, а наружу она ничего не отдаёт.

Следствие: всё, что нужно тестам или другим слоям, объявляется **глобально**
(`social`, `socialStart`, `efirScores`, …); внутренние хелперы модуля —
`local` внутри обёртки.

## 2. Регистрация

```lua
registerModule({
    id      = 'social',                  -- латиница, уникальный
    title   = 'Соцопрос',                -- подпись вкладки в сайдбаре
    strip   = 'Соцопрос и листовки',     -- полоса раздела тела вкладки
    hint    = '…',                       -- строка в «О скрипте»
    order   = 30,                        -- место среди модулей (photo 10, efir 20)

    draw    = function(w, h, now) end,   -- вкладка: только примитивы ядра
    measure = function() return px end,  -- желаемая высота тела (окно растёт)
    width   = function() return S(680) end,

    settings = function(add) end,        -- секция в общих «Настройках»
    commands = { ['social'] = fn, … },   -- свои команды чата

    onServerMessage   = fn,              -- цвет, текст (текст уже в UTF-8)
    onChatMessage     = fn,              -- playerId, текст
    onShowDialog      = fn,              -- вернуть таблицу = подменить диалог
    onPlayerDisconnect= fn,
    onTick  = fn,                        -- каждый кадр основного цикла main()
    onLoad  = fn,                        -- один раз при старте
    onTerminate = fn,                    -- перед выгрузкой скрипта
})
```

Меню позиционное: `Журнал`(1) `Поиск`(2) → модули по `order` → `Настройки` →
`О скрипте`; таблицы `MENU_ITEMS/MENU_IDS/STRIP_LABELS` собираются один раз
после регистрации всех модулей. `/sfnhelper <id>` открывает вкладку модуля,
команды из `commands` регистрируются как есть (префикс не добавляется — важно
сохранить команды, к которым редакция привыкла: `/efir`, `/social`, `/genders`).

Диспетчеры ядра вызывают обработчики под `pcall`, поэтому падение одного модуля
не роняет окно и журнал.

## 3. Вкладка: только примитивы дизайн-ядра

`draw(w, h, now)` получает ширину тела (`w` уже минус паддинги) и рисует
функциями ядра — тогда вкладка бесплатно получает DPI-масштаб, замер окна,
проверку наложений и аварийный текстовый режим:

* полосы и строки: `sectionStrip(w, label)`, `anchoredRow(id, h)`,
  `advance(dy)`, `sameRow(gap)`, `hline/vline/fillRect/strokeRect/dot/gradH`,
  `drawText/drawTextClipped/drawTextCentered`, `fitText`, `textW`;
* компоненты: `flowButton(id, label, col, onClick, w, h)`, таблицы
  `measureCols(rows, cols)` + `fitTableWidths(widths, cols, w)`;
* палитра `C` (`C.text/textDim/textFaint/ready/soon/blocked/info/violet/accent`),
  шрифты `fonts.smal/cum/big` через `pushFont/popFont`;
* поля ввода: буферы `imgui.new.char[N]()` + `readBuf(b, n)`/`writeBuf(b, n, s)`
  (опубликованы как `SFNLogs.readBuf/writeBuf` для тестов).

Обязательные мелочи, которые проверяет тест вёрстки:

* значка «‹» нет ни на одной вкладке;
* у таблиц **шапка и полосы разделов закреплены**: строки живут в
  `BeginChild` с `PushClipRect` по рамке региона (механика v2.2.2);
* тексты не наезжают друг на друга и не выходят за регион — включая модалки
  (регион попапа в моке 400 px, длинные строки приходится дробить);
* модалки и попапы имеют уникальные id (`##socialgender`, `##efirgender`);
* `measure()` честно считает высоту: окно растёт под самую «толстую» вкладку.

Прямые `imgui.Text/Button` допустимы только внутри модалок (так делают ядро и
«Эфир»); тело вкладки рисуется примитивами DrawList.

## 4. Данные и совместимость

* модуль читает и пишет **прежние** пути своего скрипта
  (`sfn_photo_data\photos.json`, `sfn_data\*.json`, `sfn_photo_data\social.json`) —
  переход с отдельных скриптов не теряет базы;
* общий ресурс — база полов `SFNHelper\genders.json`: слой «ОБЩАЯ БАЗА ПОЛОВ»
  даёт `gendersAll/gendersGet/gendersSet/gendersCount/gendersSave` и при первом
  чтении сливает оба старых файла (`sfn_data\` и `sfn_photo_data\`), не
  перезаписывая их; «Эфир» дополнительно пишет в свой прежний файл, чтобы откат
  на отдельный скрипт остался рабочим;
* общий JSON-кодек ядра (`json.encode/decode`) вместо своего `prettyJson`;
* кодировки: строки чата приходят в CP1251, ядро переводит их в UTF-8 до
  передачи в модуль (`cp1251ToUtf8`), наружу — `utf8ToCp1251`.

## 5. Игровой слой: правила безопасности

* **весь игровой файл обязан компилироваться парсером Lua 5.1**: MoonLoader
  работает на LuaJIT (5.1), а тесты — на Lua 5.4+ через lupa. Операторы
  `& | ~ << >> //`, `goto` и целочисленные литералы `0xFFi64` существуют только
  в Lua 5.2+: ветка кода, которая «в игре никогда не выполнится», всё равно
  компилируется вместе с файлом и роняет загрузку скрипта (регресс 0.3.0:
  bit-шим «только для тестов» на операторах 5.3 убил SFN_Helper.lua в игре на
  строке шима). Проверка `luac5.1 -p` входит в набор `lua51` и в CI;
* если PURE-слою нужна библиотека, которой нет в Lua 5.4 (например, `bit`),
  шим пишется **только на синтаксисе 5.1** — арифметика `+ - * / % ^` и
  `math.floor`; семантику сверяют дифференциальным фаззом с LuaJIT
  (`tests/run_lua51_syntax.py`: ~8000 кейсов на настоящем интерпретаторе 5.1);
* `wait()` — только внутри `lua_thread.create(...)` и **никогда** под `pcall`
  (иначе ломается корутина MoonLoader; на этом горели оригинальные скрипты);
* всё, что может отсутствовать в сборке (`memory`, `vkeys`, `sampGetChatInfoPtr`,
  `setVirtualKeyDown`, `getAllChars`), вызывается через `pcall` после проверки
  `if <global> then …`;
* скриншоты: модуль ставит `SFNHideUI = true` — кадр ядра учитывает флаг в
  условии отрисовки, поэтому в снимок не попадает ни одна вкладка;
* изоляция вкладок (с 0.3.2): ядро вызывает `measure`, `width` и `draw`
  модуля каждое под собственным `pcall`. Падение модуля не роняет кадр:
  вместо вкладки рисуется панель с причиной, ошибка запоминается в
  `SFNLogs.moduleErrors[id]` (подробности — `/sfnhelper ui`), остальные
  вкладки и сайдбар работают;
* конечный автомат (стадии, зачёты, прерывания) целиком в PURE-слое и возвращает
  списки событий (`{ chat = {...}, waits = {...}, save = true }`), а GAME-слой их
  исполняет: так поведение тестируется без игры и не зависит от наличия
  `lua_thread`.

## 6. Тесты и превью (обязательная часть приёмки)

* `tests/test_helper_logic.lua` (`run_helper_logic.py`) — PURE-логика всех
  модулей: из `SFN_Helper.lua` вырезается PURE-секция и выполняется отдельно;
  сейчас 861 проверка;
* `tests/test_helper_ui.lua` (`run_helper_ui.py`) — вёрстка на headless-моке
  mimgui: наложения, выход за границы, закрепление шапок при скролле, клипы,
  команды, модалки, диспетчер `onTick`; сейчас 222 проверки;
* `tests/run_lua51_syntax.py` (набор `lua51`) — игровой слой: `luac5.1 -p` по
  всем игровым `.lua` репозитория + фазз bit-шима и SHA-256 на настоящем
  интерпретаторе Lua 5.1/LuaJIT против эталонной семантики LuaJIT bit
  (~8000 кейсов, детерминированный сид); бинарники ищутся в `$LUAC51/$LUA51`,
  `../tools/` и PATH, в CI собираются из исходников шагом workflow;
* `tests/render_helper_svg.py` + `tests/render_helper_scene.lua` — SVG-превью
  всех вкладок в `delivery/proekt/preview/helper-*.svg` (собираются из реальных
  вызовов DrawList, часы сцены заморожены, поэтому файлы воспроизводимы);
* регресс SFN Logs (`run_logic.py`, `run_ui.py`, `run_api.py`,
  `run_ui_strict_colors.py`) обязан оставаться зелёным;
* `tools/sync_delivery.py --check` — копии `SFNLogs.lua` и `delivery/preview/`
  не разъехались с каноном.

Локально всё одной командой: `python3 run/all_tests.py` (наборы logic, ui,
strict, api, hlogic, hui, preview, hprev, sync, lua51). Тот же набор выполняет
CI.

Полезные соглашения мока (экономят часы):

* клики и ховеры живут только внутри кадра: передавать через
  `mock.frame({ clicks = { ['label##id'] = true } })`;
* тексты и прямоугольники копятся за все кадры — брать только последний
  (`t.frame == st.frames`);
* попап рисуется, если открыть его в opts: `{ popups = { ['##id'] = true } }`;
* список «игроков рядом» в тестах подкладывается через
  `socialSetPlayersForTests({...})` (в игре он строится по `getAllChars`).

## 7. Именование и доставка

* итоговый скрипт: `SFN_Helper.lua` в корне, `script_name('SFN Helper')`,
  версия в одном месте — `SFN_VERSION_STR` (совпадение с `script_version()`
  проверяет тест);
* автообновление: raw-адрес `main/SFN_Helper.lua`, валидация требует имя
  «SFN Helper» и версию новее текущей, бэкап `SFN_Helper.lua.bak`, состояние в
  `SFNHelper\update.json`;
* SFN Logs продолжает жить и обновляться отдельно: разные файлы, разные папки
  данных (`SFNLogs\` и `SFNHelper\`), разные хоткеи (F8 у Logs, F9 у Helper);
* хоткеи модулей не должны пересекаться: F9 — окно, F11 — «Эфир», F10 —
  «Соцопрос» (у отдельного `sfn_social.lua` был F11, при переносе заменён);
* версии: `vX.Y.Z` — SFN Logs, `helper-vX.Y.Z` — SFN_Helper; история в
  `CHANGELOG.md`. До полного переезда редакции помощник держится в `0.x`.

## 8. Что спрашиваю перед сборкой, если неясно из кода

* какие данные пользователь должен видеть в первую очередь (порядок строк и
  колонок вкладки);
* что редактируется прямо в окне, а что только командами;
* что переживает перезапуск игры (персист) и в какой файл;
* нужны ли уведомления в чат и в каких случаях;
* кто имеет доступ к вкладке (как список ведущих у «Эфира») и что показывать
  остальным.
